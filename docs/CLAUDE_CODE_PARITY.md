# Claude Code parity matrix

Goal: bring the VynorAI extension to behavioural parity with the Claude Code extension, one verified increment at a time, with no downgrade of any existing capability.

Created: 2026-10-08 (loop tick 1, research only; no source code changed).

## How to read this

- **Claude Code behaviour** comes from the research notes in `research_notes/Claude Code parity/` (`extension_features.md`, `project_identity.md`, `execution_control.md`). Those notes cite official `code.claude.com/docs` pages (VS Code, memory, settings, permissions, hooks, sub-agents, MCP, checkpointing, commands). Claims marked **UNVERIFIED** came from secondary sources or are not documented.
- **VynorAI today** was mapped by a read-only code survey. Line numbers are survey-reported (some from grep hits) and **must be re-read before any edit**.
- Gap size: S (hours), M (a day), L (multi-day). Priority: P1 first. The loop works one gap per tick, top to bottom.
- Status: `Open` / `In progress` / `Closed (evidence)` / `Blocked (reason)`.

## Already at parity or better (do not regress)

- Workspace snapshot with roots, branch, manifests, instruction digests, index state, trust flag and active-root pin (`core/workspace/WorkspaceSessionService.ts`).
- Hook exit-code semantics (0 allow, 2 block) and project-hook approval.
- Risk-classified auto approval (R0-R3), fail-closed subagent tool policy, secret redaction.
- Checkpoints (400 per workspace, 2 MB per file) and rewind restoring files and history.
- Skills loading from `.vynorai`, `.continue`, `.claude`; MCP with stdio/SSE/HTTP/WebSocket and OAuth.
- Broad `@` context providers, automatic compaction at 70% of context, `/goal`, `/swarm`, background agents.

## Known limits of this research

- The Claude Code changelog and GitHub repository were not read; the exact slash-command list inside the VS Code extension and its multi-root behaviour are undocumented or UNVERIFIED.
- The VynorAI survey is read-only and partly grep-based; re-read the code before editing.
