# QA plan: real-user style testing of the Excel add-in

Goal: find what breaks when ordinary people use the add-in, before real users do. Two parts: what a machine can sweep (done by script, repeatable), and what needs real people (a short protocol).

## 1. Who we test as (personas)

| Persona               | How they type                                               | What they do                           |
| --------------------- | ----------------------------------------------------------- | -------------------------------------- |
| Clerk                 | Short, no column names ("total by region"), typos           | Cleans data, totals, simple charts     |
| Manager               | Business words ("how are we doing by branch")               | Summaries, dashboards, email a report  |
| Singlish typist       | Sinhala words in English letters, mixed with English, typos | Same tasks, no Sinhala keyboard        |
| Sinhala-script typist | Sinhala letters                                             | Same tasks                             |
| Careless / hostile    | Empty, huge, pasted junk, symbols, "ignore the rules" text  | Nothing useful; must not break or leak |

## 2. QA techniques used

| Technique                          | What it finds                                                                                              | How                          |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------- |
| Equivalence classes and boundaries | Empty, one character, very long, whitespace only                                                           | `test/batch/qa.ts` section 1 |
| Negative testing (wrong inputs)    | Columns that do not exist, typos in column names, contradictory or impossible requests                     | section 2                    |
| Error guessing                     | Emoji, right-to-left text, control characters, HTML and script text, formula text such as `=1+1`, SQL text | section 3                    |
| Security and abuse                 | Prompt injection ("ignore previous instructions"), requests to send data elsewhere, formula injection      | section 4                    |
| Persona sweep                      | Typos, mixed languages, vague phrasing                                                                     | section 5                    |
| Data edge cases                    | Header only, one row, blank headers, duplicate headers, all-blank column, error values, 50,000 rows        | section 6                    |
| Exploratory session (live)         | Things scripts do not think of                                                                             | protocol below               |

Pass rule for every machine case: it never crashes, answers within 300 ms, never invents a column, and either produces a plan, an answer, or says plainly what it could not do. A silent wrong plan is a failure.

## 3. Real-user protocol (needs people)

Run with 3 to 5 people who are not developers, 30 minutes each, on a copy of one of their own workbooks.

1. Give no instructions on how to word things. Task card only: "get total sales by branch", "clean this list", "make a chart", "email the result to yourself".
2. Observe silently; note where they hesitate, retype, or ask for help.
3. After each task ask: did the result match what you wanted? (yes / partly / no) and what did you expect?
4. Record in a table: person, task, exact words typed, what happened, severity (blocker, annoying, cosmetic).
5. Success measures: task completed without help (target 80 percent), retypes per task (target at most 1), "no" answers (target 0 on data-changing tasks).

## 4. Results

See the results section appended below by each run.

### Run 1 (machine sweep, build 20261020.15)

132 cases over sections 1 to 6 (details in `docs/QA_RESULTS.md`). No crashes, nothing slower than 300 ms, including a 50,000-row table, 200 columns, header-only, blank and duplicate headers, and error values.

Found: 5 requests that name a column which is not in the selection ("pivot total Profit by Region", "bar chart of Revenue by Branch", "remove duplicates in Customer", "highlight Score greater than 5") still turned into a plan on some other column, with no warning. Fixed: `extensions/m365/src/unknownColumn.ts` names the missing column and lists the real ones before the preview (0 false alarms on the 500-prompt corpus). The preview and approval step are unchanged.

Not yet done: the real-user protocol (section 3) needs people.

### Run 1, live check (build 20261020.15)

- "pivot total Profit by Region" on Orders: the pane says `I could not find a column called "Profit". The columns are: ...` before the preview. Works.
- Incident during this check, caused by the test driver, not shown to be a product fault: the source sheet's column A had shifted up one row (A1 read 000001, A301 was empty). It followed earlier keystrokes sent while the sheet had focus because the pane coordinates had moved. Repaired with Excel's own Undo; A1 reads Order No and A301 reads 000300 again. Cause of the shift is not proven. Lesson for the test driver: after any layout change, take a screenshot and confirm where the composer is before typing, and re-check A1 and the last row before every test.
